Project Requirements:
1. The website design is fully fluid, responsive, mobile-first, and accessible.
    The design Should follow these breaking points:
    - 768px
    - 1024px
2. The Contacts buttons behavior. On wide screens, more than 900px the buttons should be sticky
in the center of the viewport as they are now, keeping the place on the screen when a user scrolls the page. They should however keep a constant reasonable distance from the 'main section' with the text, roughly 2 rem or
whatever will be close to the main section but not too close. On 900px+small margin distance, these buttons should start keeping a constant margin from the right edge of the viewport
until they reach the next breaking point 768px, when they disappear and give place to the drawer component with the buttons. This should provide a neat squeezing effect.
On smaller screens, 768px and less, these buttons disappear, and the drawer trigger component is shown instead. Current drawer component behavior is correct.
3. Main subheader (AI Automation Engineer | Customer Advocate | Team Lead) line breaking logic should be as follows: the  'Customer Advocate' and  'Team Lead' must only be moved to a new line completely. Moving only 'Lead'
or only 'Advocate' is unacceptable. When any one of those items gets moved to a new line, the preceding '|' divider must disappear via the most reliable method, so that the first line doesn't get left ending with the divider.
4. Each contact  button, default ones, and in the burger menu, must have a light animation on hover: 
    - a displacement to the left by half it's width;
    - a 60bpm pulsating increase in size by 7%;
    - a 3D blend mode animation (see code example in \3D-blend-mode-animation.css).

5. All Skills section elements, such as '/html/body/main/div[1]/section/section[4]/div/div[1]' must get a dynamic gradient background on hover looping through these colors in the exact order:
#fb2c36, #f54900, #ff8904, #ffb900, #ffdf20, #497d00, #9ae600, #00a63e, #002c22, #009966, #005f78, #1c398e, #00a6f4, #312c85, #4d179a, #9810fa, #e12afb, #e60076, #861043, #ec003f. 
It may be applied as a separate animation for each element, or a single gradient with masking on all of the elements: whatever option is more reliable and easy to implement.
6. The codebase is optimized and all dependencies and libraries are updated to the latest stable versions that work together seamlessly. There are no elements, styles, files, or whatever else redundancies that don't serve a function or make the code clunky.
